2. Executive summary

This report is an independent, analysis-only audit of three completed SSFL (semisupervised federated learn-
ing) runs – one per non-IID scenario of the mini-N-BaIoT intrusion-detection benchmark – transferred from
an NVIDIA RTX 3090 machine, compared against the results published by Zhao et al. in the IEEE Internet of
Things Journal (vol. 10, no. 10, May 2023, pp. 8645-8655). No training was rerun and no transferred artifact
was modified; every number below was recomputed from the transferred metrics, telemetry and configuration
records.
Headline outcome. The reproduction is close to the paper on final accuracy: round-200 accuracy is 87.92%
/ 83.69% / 83.76% for scenarios 1-3 against the paper’s 87.40% / 86.70% / 84.22%, a difference of +0.52 /
-3.01 / -0.46 percentage points. Macro F1 lands within -0.61 / -3.95 / -0.79 percentage points of Table II.
Convergence is slower than the paper’s Table III at every intermediate milestone, with the gap closing only
in the last quarter of training.
Principal finding. In all three scenarios the pseudo-label consensus mechanism permanently merges the
two gafgyt flooding classes (gafgyt.tcp and gafgyt.udp) within the first ten rounds: the federation’s global
pseudo-labels assign essentially all open-set samples of both classes to a single surviving class, so one of the
two ends the run with recall 0.00. Scored with the merged pair treated as one class, final accuracy would be
98.02% / 93.80% / 93.88% – the single largest quality loss in the reproduction, and the main driver of the
macro-precision gap versus the paper (Section 17).
Secondary findings. Scenario 3’s test loss diverges (final 27.02, about 16x its round-13 minimum) while
its accuracy is stable – a growing-overconfidence signature, not a performance failure (Section 19). Commu-
nication matches the protocol contract exactly (8,900 uplink bytes per client per round); under the paper’s
own accounting convention the cumulative cost is 1.78 MB at round 200 versus the 0.47-0.55 MB the paper
reports at its top-accuracy rounds (Section 12). The artifact-integrity audit passed 32 of 45 checks with 13
warnings and no failures (Section 8). All results rest on one seed per scenario; no statistical significance is
claimed anywhere in this report.

3. Research question and scope

The question examined is narrow: do the transferred SSFL runs reproduce the SSFL results the
paper reports – Table II (final accuracy, F1, precision), Table III (accuracy at rounds 10, 50, 100, 150, 200)
and Table IV (communication cost) – and where they do not, what in the recorded telemetry explains the
difference?
Scope and ground rules of this analysis:

    Analysis only: no training was rerun, and no experiment source code, configuration, telemetry or trans-
     ferred result was modified. Every new file lives under artifacts/analysis/ssfl solution report/.
    The transfer intentionally excluded the raw dataset arrays and all model weight checkpoints. Claims
     about raw features or weights are therefore out of scope; the analysis uses the recorded dataset manifests,
     metrics, aggregation audits and telemetry.
    Only the SSFL algorithm is covered. The repository also implements FL, FD and DS-FL baselines, but
     no baseline runs were part of the transferred solution suite.
    One run per scenario (seed 2023). Round-to-round variation within a single run is reported as stability,
     never as statistical uncertainty; no confidence intervals or significance tests are presented, because
     rounds of one run are not independent samples.
    Paper values were transcribed from the PDF in the repository root and are quoted only where they
     were verified there.


4. Paper and method overview

Zhao et al. propose SSFL, a semisupervised federated intrusion-detection method for IoT in which clients
hold unlabeled private traffic and only the server holds a small labeled dataset. The method reproduced
here follows the paper’s specification as implemented in this repository:

    Each communication round has two phases. In the proposal phase every client runs its local model
     over the shared open set (8,900 samples) and uploads one hard pseudo-label per sample. A per-client
     discriminator marks samples as familiar or unfamiliar, and a confidence threshold set at the median
     of the client’s predicted probabilities suppresses low-confidence proposals.
    The server aggregates proposals by majority vote into a global pseudo-label vector plus a validity
     mask, and broadcasts both. In the distillation phase each client trains its local model for 5 local
     epochs against the valid global pseudo-labels (plus its private data), so knowledge moves through labels
     only – model parameters never cross the wire.
    The backbone is the paper’s CNN: eight one-dimensional convolution layers with an MLP head, an
     11-way traffic classifier and a 2-way discriminator, on 115 input features reshaped to 23x5.

The paper evaluates on N-BaIoT (9 IoT devices, 1 benign plus 10 botnet traffic classes from the gafgyt
and mirai families) under three non-IID client partitions, and reports SSFL beating FL, FD and DS-FL
baselines with final accuracy 87.40% / 86.70% / 84.22% (Table II), the convergence profile in Table III, and
a communication cost orders of magnitude below parameter-exchanging FL (Table IV). This reproduction
targets those three tables for SSFL only.

The runs executed on a single Linux workstation with an NVIDIA GeForce RTX 3090 – the same GPU
model the paper used, which makes the runtime comparison in Section 21 unusually direct. The paper’s
stated environment is Python 3.7 with PyTorch 1.x on an Intel Core i9-11900K with 64 GB RAM and an
RTX 3090; the reproduction used a substantially newer stack:

6. Dataset and partitioning

The runs used the repository’s mini-N-BaIoT preparation: 89 source CSV files across 9 devices and 11 traffic
classes, 1000 records sampled per device-class subset, 89,000 records in total, split 62,300 private / 8,900
open / 17,800 test (70/10/20), min-max normalized (mode all mini), preparation seed 2023. The dataset
manifest hash d7966afc8a735de3... is identical in all three run directories, so all scenarios trained and
were tested on exactly the same prepared data.
Client partitions follow the paper’s three non-IID scenarios: scenario 1 splits each device’s private data into
label-sorted shards for 3 clients per device (27 clients); scenario 2 gives each device-class subset its own client
(89 clients); scenario 3 draws client class mixtures from a Dirichlet distribution with alpha = 0.1 (89 clients).
The open set (8,900 samples) is read by every client from shared storage rather than transmitted, which is
why the paper’s one-off open-set distribution cost has no counterpart in the recorded traffic (Section 12).
Its composition follows the subset structure – 100 samples per device-class subset, hence 900 for benign and
for each gafgyt class but 700 for each mirai class, mirai being absent from two of the nine devices; test-set
supports scale the same way (1,800 versus 1,400).
The raw feature arrays themselves were not transferred, so this report makes no claim about feature values –
including any claim that gafgyt.tcp and gafgyt.udp rows are near-identical in feature space; that hypothesis
is discussed in Section 17 strictly as a hypothesis.


7. Resolved experimental configuration

Table T1 compares every configuration choice against the paper’s specification. The resolved configuration
is the same in all three runs except for scenario and the derived client count: backbone cnn, 200 rounds, 5
local epochs, Adam at learning rate 0.0001, batch size 80, hard pseudo-labels, median confidence threshold,
discriminator and majority voting enabled, seed 2023, deterministic = true.
One assumption deserves emphasis: the paper is internally inconsistent about batch size (80 in Table I’s
footnote, 100 in the Section V prose); the reproduction uses 80 and records the alternative as the unused flag
paper text batch. All other hyperparameters match the paper’s stated values exactly.

8. Artifact-integrity audit

Before any comparison, the transferred artifacts were audited for completeness and internal consistency: 45
checks, of which 32 passed, 13 produced warnings, and none failed. Every scenario has all 200 rounds
of metrics (200 rows), per-class metrics (2,200 rows), communication records, aggregation audits and server
lifecycle events; client participation is complete (27/89/89 clients in every round); the error tally is zero
across all telemetry; and the dataset manifest hash matches across runs. No metric value anywhere is NaN
or infinite.
The 13 warnings fall into four groups, none of which undermines the results:

    Checkpoint retention (3): telemetry records the policy milestones plus latest, not the expected
     latest only; 195 of 200 per-round checkpoints were pruned, keeping milestones 10/50/100/150/200.
     This only affects which checkpoints exist on the source machine – none were transferred.
    Git provenance (3): all runs were executed from commit 78df829dd1ce with a dirty working tree
     (git dirty = true), so the exact executed code cannot be pinned to a commit.
    code version.json (3): the file is present but empty in each run directory, providing no additional
     code fingerprint.
    Determinism metadata (3 + 1 global): environment.json is captured before determinism is con-
     figured, so its deterministic algorithms enabled = false cannot confirm the deterministic setting;
     moreover configure determinism() is called only in the server process, while Ray client actors receive
     seeding but not deterministic-kernel enforcement. Bit-exact re-runnability is therefore not established
     (Section 22).

9. Overall results

Figure F1 shows the three accuracy trajectories with the paper’s Table III milestones overlaid; Figures F2-
F4 give per-scenario panels and the macro-averaged F1, precision and recall curves. The reproduction’s
qualitative story matches the paper – scenario 1 ends highest, scenarios 2 and 3 within about half a point of
each other – but the path differs: all three runs spend the middle of training 4-10 percentage points below
the paper’s curve and close most of the gap in a late surge after round 150.

                   Scenario 1 finishes at 87.92% accuracy / 85.89% macro F1, with its best round being the final one
                    (round 200).
                   Scenario 2 finishes at 83.69% / 81.00%, best 84.25% at round 196.
                   Scenario 3 finishes at 83.76% / 81.68%, best 83.89% at round 196.

Normalized area under the accuracy-versus-round curve – a path-sensitive summary – is 77.59% / 74.80%
/ 78.39%: scenario 3 is actually the best run by this measure despite the lowest paper target, because its
early convergence is fastest. Stability over the final windows (Table T11) is good in all runs: last-10-round
accuracy standard deviation is 0.32 / 0.43 / 0.29 percentage points, and the final round is within 0.6 points
of the best round everywhere, so the runs did not end on an unlucky dip.

10. Table II comparison (final metrics)

Table T2 reproduces the paper’s Table II. Accuracy differences are +0.52 / -3.01 / -0.46 percentage points
– scenario 1 slightly above the paper, scenario 3 within half a point, scenario 2 the outlier at about three
points below. Macro F1 tracks the same pattern.
Precision is the sore spot: the reproduction’s macro precision trails the paper’s reported precision by -7.92
/ -12.19 / -9.39 percentage points. Two effects stack here. First, the paper does not state its averaging
convention; Table T2b therefore reports macro, micro and weighted variants of precision, recall and F1, and
no convention reaches the paper’s 90-92% precision while accuracy and F1 do align – so the convention
alone does not explain the gap. Second, the TCP/UDP class merge (Section 17) puts every sample of two
classes into one predicted class, which caps that class’s precision near 50% and mechanically drags the macro
average down by roughly 4-5 points. A run without the merge would plausibly close most of the precision
gap, which is why the merge – not a generally weaker classifier – is identified as the main driver.

12. Table IV communication comparison

The paper’s Table IV counts, for a representative client, the cumulative uplink of label vectors during training:
C@50, C@75 (cost until 50%/75% accuracy) and C@Top-Acc, plus a one-off 0.96 MB C@D-o for distributing
the open dataset. The reproduced protocol sends exactly one 8,900-byte int8 hard-label vector per client per
round, so the paper-accounting cumulative cost is 1.78 MB (= 1.6975 MiB) over 200 rounds in every scenario.
Reproduced milestones are the same order of magnitude as, but consistently above, the paper’s: C@50 =
0.0267 / 0.0356 / 0.0267 MB against the paper’s 0.01 MB, and C@Top-Acc = 1.78 / 1.74 / 1.74 MB against
0.55 / 0.49 / 0.47 MB. The C@Top-Acc ratio of roughly 3x follows directly from when top accuracy occurs:
the paper’s runs peak mid-training while the reproduction peaks at rounds 196-200, so the cumulative count
runs to the end. The C@50/C@75 gaps mirror the slower convergence of Section 11 plus the paper’s unstated
byte unit and possible per-label encoding. C@D-o has no reproduced counterpart: the open set was read
from shared storage, not transmitted, and no plausible encoding of the transferred quantities reconstructs
0.96 MB (Table T14’s caption). The qualitative claim that survives untouched is the paper’s central one –
SSFL’s traffic is labels, not parameters, three to four orders of magnitude below parameter exchange.

13. Scenario 1 analysis (label-sorted shards, 27 clients)

Scenario 1 – three clients per device, each holding two label-sorted shards – is the paper’s mildest partition
and the reproduction’s best run, and the only one to beat its paper target.

    Final accuracy 87.92% (paper 87.40%, difference +0.52 pp); macro F1 85.89%; best accuracy 87.92%
     at round 200.
    Reached 70% at round 15, 80% at round 117; minimum test loss 1.904 at round 4; final test loss 3.199.
    Valid pseudo-label rate at round 200: 99.82%.
    The TCP/UDP merge picks the opposite survivor to scenarios 2-3: pseudo-label class gafgyt.tcp goes
     to zero at round 4 and gafgyt.udp absorbs the pair.

Its trajectory is the most dramatic: near-flat progress through rounds 25-150 (roughly 71% to 82%), then a
sharp climb of five points over the final 25 rounds, ending at its global best on round 200 exactly. Aside from

budget ended.


14. Scenario 2 analysis (one client per device-class subset, 89 clients)

Scenario 2 – every one of the 89 device-class subsets is its own single-class client – is the hardest partition
for pseudo-label consensus, since no client ever sees two classes, and it is the run furthest from the paper.

    Final accuracy 83.69% (paper 86.70%, difference -3.01 pp); macro F1 81.00%; best accuracy 84.25% at

16. Per-class and confusion-matrix analysis

Table T5 lists final precision/recall/F1 for all 11 classes in each scenario; Figures F9-F12 give the raw and
row-normalized confusion matrices, grouped F1 bars, and a metric heatmap.
The dominant structure is the same in all three scenarios: the gafgyt.tcp / gafgyt.udp pair accounts for
the largest single block of error everywhere. The surviving class of the pair shows recall ˜1.00 but precision
˜0.50 (it receives both classes’ samples); the collapsed class scores exactly zero. This binary signature – one
class at zero, its sibling at half precision – is what distinguishes a merge from ordinary confusion, where both
classes would retain partial recall. Benign traffic is classified near-perfectly in all runs (F1 0.994-0.996), which
matters for an intrusion-detection use case: false alarms stay rare regardless of the attack-class confusions.
Outside the pair, scenario quality diverges. In scenario 1 all nine remaining classes score F1 0.949 or higher.
Scenarios 2 and 3 add ordinary partial confusions – not merges – concentrated in two places: mirai.ack versus
mirai.udp (scenario 2 F1 0.685 and 0.715; scenario 3 0.861 and 0.849) and, in scenario 3 only, gafgyt.junk
pulled toward gafgyt.combo (junk recall 0.70, combo precision 0.764). Together these cost scenario 2 and 3
roughly 3-4 accuracy points beyond the merge, which is why their merged-pair rescoring in Table T21 lands
near 93.8% rather than scenario 1’s 98.0%.

17. TCP/UDP class-collapse investigation

The central defect found in the reproduction is a pseudo-label consensus collapse of the two gafgyt
flooding classes. The aggregation audits record, per round, how many open-set samples the global vote
assigns to each class; the open set contains 900 gafgyt.tcp and 900 gafgyt.udp samples, and within a handful
of rounds one of the two classes’ global pseudo-label count falls to (and stays at) essentially zero while its
sibling’s rises to about 1,800:

           Scenario 1: gafgyt.tcp count reaches zero at round 4; survivor gafgyt.udp.
           Scenario 2: gafgyt.udp count reaches zero at round 10 (after a one-round reversal at round 9 in which
            udp briefly dominated); survivor gafgyt.tcp.
           Scenario 3: gafgyt.udp count reaches zero at round 3; survivor gafgyt.tcp.

The merged pair’s total pseudo-label count stays at 1,798-1,801 throughout – the samples are never lost or
scattered, they are relabeled as one class. Once the global labels stop containing the collapsed class,
SSFL reproduction report                                                                                                                                                                                                 23



distillation actively teaches every client that the class does not exist, and the state is absorbing: no round in
any scenario ever recovers it (Figures F14, F15). In scenarios 1 and 2 the consensus zero precedes or coincides
with the test-set recall collapse; in scenario 3 the test recall is zero from round 1, before the consensus zero
at round 3 – there the initial model state, not consensus feedback alone, sealed the outcome.
The mechanism is consistent with hard-label majority voting on a near-inseparable class pair: if the two
flooding attacks look alike in feature space, whichever class wins slightly more votes in early rounds gets all
the merged samples, and hard labels leave no trace of the minority vote (a soft-label protocol would). Which
sibling survives differs across scenarios – evidence for a random early tip, not a systematic bias. Because
the raw feature arrays were not transferred, the near-inseparability premise is stated as a hypothesis, not a
measured fact.
Cost of the collapse (Table T21): rescoring the final confusion matrix with the pair merged into
one class yields accuracy 98.02% / 93.80% / 93.88% and 10-class macro F1 97.80% / 92.43% / 93.19%,
with the merged pair itself scoring precision and recall above 0.998 everywhere. In other words, the
models detect gafgyt flooding essentially perfectly and only fail to tell its TCP and UDP variants apart;
that single distinction costs about 10 points of headline accuracy. Full per-round trajectories are in
tables/t18 tcp udp confusion trajectory.csv.

18. Pseudo-label consensus analysis

Outside the collapsed pair, the consensus mechanism works well. The fraction of open-set samples with
a valid global pseudo-label (Figure F7) climbs above 99% within the first rounds and stays there – final
values 99.82% / 99.93% / 99.60% – so the median-threshold discriminator filter rejects almost nothing at
equilibrium. Figure F13 shows the global pseudo-label class distribution over rounds: after the first ˜10
rounds it is essentially stationary, with each healthy class holding close to its true open-set share (900 for
benign and each gafgyt class, 700 for each mirai class) and the surviving flooding class holding ˜1,800. Table
T13 quantifies per-class pseudo-label counts at milestone rounds against the known open-set composition:
healthy classes deviate by at most a few samples, confirming that the consensus is accurate wherever it has
not merged.
The one dynamic worth flagging: the collapse happens while the valid rate is climbing – by the time the filter
is passing 99% of samples, the merged labeling is already locked in. The validity mask therefore provides no
protection against consensus collapse; it filters low-confidence individual proposals, not systematically wrong
confident ones.

19. Loss and calibration discussion

Figure F5 plots server-side test loss (linear and log views) and Figure F6 the client-side training/distillation
loss; Table T22 collects window means. All three runs show the same qualitative decoupling: test loss
bottoms out very early (rounds 4-13, minima 1.90 / 1.17 / 1.65) and then trends upward for the rest of
training, while test accuracy keeps improving. In scenarios 1 and 2 the drift is bounded – last-50-round loss
means of 4.11 and 4.12, with the final rounds no worse than mid-training. Scenario 3 is different in degree,
not kind: its loss diverges monotonically in windows (5.82 over rounds 101-150, 12.76 over 151-200, final
27.02), with 33 of the last 100 rounds above 10.
The signature – rising cross-entropy at stable-or-improving accuracy – indicates growing overconfidence:
the model concentrates probability mass on its predicted class, so each residual error contributes an exploding
SSFL reproduction report                                                                                                                                               28



log-loss term, and the collapsed UDP class guarantees a permanent floor of confidently wrong predictions (900
test samples predicted as TCP with high confidence). Five local epochs per round of distillation against hard
pseudo-labels is exactly the training pressure that sharpens outputs this way, and scenario 3’s Dirichlet clients
– many holding a few dominant classes – sharpen fastest. Two caveats: first, since per-sample probability
vectors were not stored, calibration error cannot be directly measured from the transferred artifacts;
the overconfidence account is an inference from the loss/accuracy decoupling, not a computed ECE. Second,
the training loss (Figure F6) stays small and flat everywhere, confirming the divergence is a test-set confidence
phenomenon, not optimizer instability. Practical implication: test loss is not a usable early-stopping
or model-selection signal for this protocol; accuracy or F1 must be monitored directly.

20. Communication-efficiency analysis

Beyond the paper-convention comparison of Section 12, the transferred communication records allow a
full federation-wide accounting. Three conventions are reported throughout (Table T14): the paper’s

Total wall-clock time was 7.96 h (scenario 1), 20.95 h (scenario 2) and 20.85 h (scenario 3) – about 2.6x longer
for the 89-client scenarios, which run 3.3x the clients at the same concurrency cap of 8. Round durations
SSFL reproduction report                                                                             34



(Figure F18) are remarkably uniform: mean 143 s / 377 s / 375 s with standard deviations of 0.9-4.0 s
and zero scheduling gaps between rounds (maximum inter-round gap 1.4 ms across all 600 rounds) – the

GPU telemetry at 1 Hz (27,995 / 73,558 / 73,202 samples) shows the device saturated and comfortable

runtime comparison to the paper is possible.

22. Deviations and reproducibility warnings

Deviations from the paper, and internal reproducibility gaps, in decreasing order of likely impact on the
comparison:

                         Software generations apart: Python 3.12.13 / torch 2.6.0+cu124 versus the paper’s Python 3.7 /
                          PyTorch 1.x. Different kernels, initializers and numerics; a deliberate repository policy, but it makes
                          bit-level agreement with the paper impossible in principle.
                         Single seed: one run per scenario, seed 2023. Which flooding sibling survives the collapse already
                          varies across scenarios, demonstrating that run-to-run variance is material – and unquantified.
                         Batch size 80 vs 100: the paper contradicts itself; 80 (Table I) was chosen over 100 (prose).
                         Determinism not end-to-end: deterministic kernels are configured in the server process only; Ray
                          client actors get seeds but not torch.use deterministic algorithms. The environment snapshot
                          additionally predates determinism configuration, so recorded flags cannot confirm the runtime state.
                          Re-running would not be guaranteed bit-identical.
SSFL reproduction report                                                                                     38



    Dirty working tree: git dirty = true at commit 78df829dd1ce and an empty code version.json
     mean the exact executed code is not pinned.
    Open set via shared storage: eliminates the paper’s C@D-o cost from the record (Section 12).
    Checkpoint policy: milestones plus latest retention; and no checkpoints (or weights of any kind)
     were transferred, so weight-level analysis is impossible here by design.
    Mini-dataset sampling: the 1,000-records-per-subset mini-N-BaIoT is the repository’s paper-faithful
     construction, but the paper’s own sampling seed is unknown, so the underlying data sample necessarily
     differs.


23. Threats to validity

    No statistical basis for small differences. With one seed per scenario, differences of a point or two
     between reproduction and paper (or between scenarios) are within plausible seed noise; only the large,
     structural findings (the collapse, the convergence-shape difference, the loss divergence) are robust to
     this threat. No significance is claimed anywhere.
    Paper ambiguities force assumptions: averaging convention behind Table II’s precision (Section
     10), batch size, MB unit (10ˆ6 vs 2ˆ20 bytes – both reported in Table T14), and the exact byte encoding
     behind Table IV.
    Different underlying sample of N-BaIoT (unknown paper sampling), so per-class test sets differ
     from the paper’s even at identical protocol behavior.
    Raw features and weights not transferred: the near-duplicate-features explanation for the
     TCP/UDP merge, and any weight-space analysis, remain unverifiable from this artifact set.
    Transcription surface: paper values were re-typed from the PDF; each was verified against the PDF
     text, but OCR-level errors in the source PDF itself would propagate.
    Analysis code as a single point of failure: all derived numbers come from one script
     (scripts/build report.py); it cross-checks itself against the suite report and run summaries
     (Section 8), and key aggregates were independently spot-verified during development, but it is one
     implementation.


24. Conclusions

The transferred runs reproduce the paper’s headline claims in substance: final accuracy within half
a point in two of three scenarios (above the paper in one), macro F1 within a point in those two, the paper’s
non-IID ordering of scenarios preserved, and the label-only communication design confirmed at three to four
orders of magnitude below parameter exchange. Scenario 2 misses its target by 3.01 points, and mid-training
convergence is uniformly slower than Table III.
The reproduction also surfaces a structural failure mode the paper does not report: hard-label majority-vote
consensus permanently merges the two gafgyt flooding classes in every scenario within ten rounds, costing
roughly ten points of headline accuracy and most of the precision gap versus Table II. Whether the paper’s
runs avoided this (by seed luck, by feature differences in their sample, or by an unstated mechanism) cannot
be determined from the paper. Secondary findings – test-loss divergence under stable accuracy (extreme in
scenario 3), the ineffectiveness of the validity mask against confident consensus errors, and the absorbing
nature of the merged state – all point at the same design pressure: hard pseudo-labels plus majority voting
discard exactly the uncertainty information that would let the federation recover a lost class.


25. Recommended next experiments

In priority order:

    A. Multi-seed replication (highest value, lowest novelty). Re-run all three scenarios with at
     least 3-5 seeds. This is the only way to (i) attach uncertainty to every comparison in this report, (ii)
     measure the frequency of the TCP/UDP collapse and the survivor distribution, and (iii) test whether
     scenario 2’s 3-point deficit is systematic or seed luck. The existing suite tooling supports this directly.
SSFL reproduction report                                                                                    39



    B. Collapse mitigation ablations. The repository already exposes the relevant switches: soft-label
     representation (ssfl label representation), voting mode, discriminator mode, and threshold policy.
     Candidate interventions, cheapest first: soft labels (retain minority-vote mass); per-class rather than
     global median confidence thresholds; class-presence monitoring with a guard that freezes distillation for
     a class whose global count falls below a floor. Success criterion: both flooding classes retain nonzero
     recall at round 200 without losing the ˜98% merged-pair detection quality.
    C. Instrument calibration and the scenario 3 loss divergence. Store per-sample probability
     vectors (or at least per-class confidence histograms) at milestone rounds, enabling a real ECE mea-
     surement; add temperature scaling or label smoothing to distillation and observe the effect on the loss
     divergence. Also worth one cheap run: raise max concurrent clients above 8 to cut the 20.9-hour
     89-client wall time; GPU headroom (Section 21) suggests near-linear gains.

26.4. A.4 Formulas and units

    Accuracy, precision, recall and F1 are computed from the stored per-round confusion matrices; macro
     averages weight classes equally, micro averages pool all samples, weighted averages weight by test-set
     support. Percentages in prose are rounded to two decimals; CSVs keep full precision.
    Percentage-point (pp) differences are arithmetic differences of percentages, reproduction minus paper.
    Normalized accuracy AUC = trapezoidal area under accuracy versus round, divided by the 200-round
     span.
SSFL reproduction report                                                                                 42



    MiB = 2ˆ20 bytes; MB = 10ˆ6 bytes. The paper’s unit is unstated; comparisons report both where it
     matters (Table T14). Logical bytes = protocol payload; serialized bytes = Flower wire representation
     including framing.
    Paper-accounting communication = one client’s train-phase uplink (8,900 bytes per round), cumulated
     – the convention that best matches Table IV’s construction.
    Convergence round at threshold X = first round with accuracy >= X.
    Window statistics (last 10/20/50 rounds) are computed over server evaluation rounds inclusive of round
     200.
